Learn the Masscode graph language

Decisions the code has to keep.

The Masscode graph language is how a project is written down: every objective, requirement, decision, rule, task and proof as a small statement a program can check. Because decisions live in the same graph as the code's evidence, a decision is no longer a document. It is a promise the code is held to on every commit.

Facts

Every line is a statement.

A subject, a relationship and an object, written in plain YAML and turned into standard RDF. Each one is true or false on its own, and each one knows who wrote it.

A closed vocabulary

Nothing is invented.

A small owned core, versioned like software and approved by a person. A key the vocabulary does not know is an error, and a new term enters as proposed until someone approves it.

Checked by programs

No model decides.

A verifier derives what follows and checks every rule. The verdict is pass, fail or unknown, and unknown is never counted as a pass.

A complete cross-cutting ontology

One vocabulary from why to proof.

Most tools keep requirements, architecture, tickets, security controls and test results in separate systems that never agree. Masscode describes all of them with one vocabulary, in twelve layers that each point back at the layers before. Concerns like personal data, security and cost are not bolted onto one layer: rules carry them across every layer they touch.

Built on open standards

A small owned core, a thin link to standards.

Masscode owns fewer than forty classes. Everything else comes from standards that other people maintain and auditors already recognise. Each Masscode class is declared a special case of a standard class, never its equivalent, so tools that only know the standard still read the graph and no other standard's mistakes are imported.
